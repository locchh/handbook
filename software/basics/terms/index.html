    Terms¶

    Software, coding, and SDLC vocabulary with abbreviations expanded, grouped by domain. Each term links to the section of this handbook that defines or discusses it. Terms the handbook doesn't cover yet link to an external reference, marked ↗.

    SDLC & Process¶

    Term Meaning Read more
    SDLC Software Development Life Cycle: Analysis → Design → Development → Testing → Deployment → Maintenance Lifecycle → SDLC Phases
    Waterfall Sequential phases, each finished before the next starts Methodologies → Waterfall
    V-Model Waterfall where every phase has a matching test level Methodologies → V-Model
    Agile Mindset of short iterations, working software, and responding to change Methodologies → Agile, Lifecycle → Agile, Scrum, Kanban
    Lean Eliminate waste, optimize the whole flow of value Methodologies → Lean
    Scrum Agile framework of fixed-length sprints with defined roles, events, and artifacts Methodologies → Scrum
    Kanban Continuous flow on a visual board with WIP limits Methodologies → Kanban
    SAFe Scaled Agile Framework: Agile coordinated across many teams Methodologies → SAFe
    PI Program Increment: a SAFe timebox of about 10 weeks (several sprints) that all teams plan and deliver together, kicked off by PI Planning Methodologies → SAFe, Wikipedia: SAFe ↗
    XP Extreme Programming: pairing, TDD, continuous integration, small releases Methodologies → XP
    Shape Up Basecamp's fixed-appetite, six-week cycles with no backlog Methodologies → Shape Up
    RUP Rational Unified Process: iterative phases with formal milestones Methodologies → RUP
    Sprint Fixed timebox (usually 1–4 weeks) that produces a usable increment Lifecycle → Agile, Scrum, Kanban
    Backlog Ordered list of work. The Product Backlog holds everything wanted; the Sprint Backlog holds what this sprint commits to Lifecycle → Agile, Scrum, Kanban, Scrum Guide ↗
    Increment The usable, done work produced in a sprint Lifecycle → Agile, Scrum, Kanban
    Sprint Planning Scrum event at the start of a sprint: pick backlog items and agree the sprint goal Lifecycle → Agile, Scrum, Kanban, Scrum Guide ↗
    Daily Standup / Daily Scrum 15-minute daily sync: progress toward the sprint goal and blockers Lifecycle → Agile, Scrum, Kanban, Scrum Guide ↗
    Sprint Review / Demo Show the increment to stakeholders and adapt the backlog from their feedback Lifecycle → Agile, Scrum, Kanban, Scrum Guide ↗
    Retrospective (Retro) End-of-sprint meeting where the team inspects how it worked (what went well, what didn't) and commits to improvements Lifecycle → Agile, Scrum, Kanban, Methodologies → Scrum, Scrum Guide ↗
    Backlog Refinement (Grooming) Ongoing work to split, clarify, and estimate upcoming backlog items Scrum Guide ↗
    Burndown / Burnup Chart Work remaining / work completed plotted over time in a sprint or release Wikipedia: Burndown chart ↗
    Lead Time / Cycle Time Request → delivered / work started → delivered: the Kanban flow metrics Lifecycle → Agile, Scrum, Kanban, Wikipedia: Lead time ↗
    DORA Metrics Deployment frequency, lead time for changes, change failure rate, time to restore: the four keys of delivery performance DORA: Four keys ↗
    DoD Definition of Done: the shared quality bar every increment must meet Scrum Guide ↗, Atlassian: DoD ↗
    DoR Definition of Ready: what a backlog item needs before a sprint can take it Atlassian: DoR ↗
    WIP Work In Progress, which Kanban limits Methodologies → Kanban
    DevOps Dev and Ops share ownership of building and running software Methodologies → DevOps
    Iteration / Timebox One cycle of build-and-review / a fixed, non-extendable slot of time Lifecycle → Agile, Scrum, Kanban
    Sprint Goal / Product Goal The single objective of a sprint / the long-term target the backlog serves Scrum Guide ↗
    Kanban Board / Swimlane Columns for workflow states (To Do → Doing → Done) / horizontal rows grouping work by type or owner Methodologies → Kanban, Wikipedia: Kanban board ↗
    CFD Cumulative Flow Diagram: work items per state over time; widening bands show bottlenecks Wikipedia: Cumulative flow diagram ↗
    Planning Poker / T-shirt Sizing Team estimation by simultaneous cards / rough XS–XL sizing Wikipedia: Planning poker ↗
    INVEST Good user stories are Independent, Negotiable, Valuable, Estimable, Small, Testable Wikipedia: INVEST ↗
    Three Amigos Business, dev, and QA review a story together before work starts Agile Alliance: Three Amigos ↗
    ART / Release Train Agile Release Train: the team of teams in SAFe that plans and ships together each PI Wikipedia: SAFe ↗
    Kaizen Continuous small improvements, the Lean habit behind retrospectives Wikipedia: Kaizen ↗
    Value Stream All steps from request to value delivered; mapped to find waste Wikipedia: Value-stream mapping ↗
    Shift Left Move testing, security, and quality checks earlier in the lifecycle Wikipedia: Shift-left testing ↗
    Code Freeze / Feature Freeze No changes except critical fixes / no new features, before a release Wikipedia: Freeze ↗
    RC / GA Release Candidate (final test build) / General Availability (released to everyone) Wikipedia: Software release life cycle ↗
    LTS / EOL Long-Term Support release / End Of Life, when support stops Wikipedia: Long-term support ↗, Wikipedia: End-of-life product ↗
    Deprecation Marking a feature as obsolete before removal so users can migrate Wikipedia: Deprecation ↗
    Dogfooding Using your own product internally before customers do Wikipedia: Dogfooding ↗
    Maintenance The SDLC phase after release: fixes, monitoring, small improvements Lifecycle → SDLC Phases

    ROI / TCO Return on Investment / Total Cost of Ownership (build + run + maintain) Wikipedia: ROI ↗, Wikipedia: TCO ↗
    CapEx / OpEx Capital Expenditure (buy assets up front) / Operating Expenditure (pay as you go, e.g. cloud) Wikipedia: CapEx ↗

    MVP Minimum Viable Product: smallest product that tests the core hypothesis with real users (also Model-View-Presenter, see Frontend) Wikipedia: MVP ↗
    CTO / EM / IC Chief Technology Officer / Engineering Manager (people lead) / Individual Contributor (hands-on track) Wikipedia: CTO ↗
    Junior / Mid / Senior / Staff / Principal Engineering career levels, from guided work to org-wide technical leadership Becoming Senior → The Ladder
    PL Project Leader or Team Leader: leads a dev team day to day, under the PM Wikipedia: Team leader ↗
    SME Subject Matter Expert: the go-to person for a domain Wikipedia: Subject-matter expert ↗
    BrSE / Comtor Bridge System Engineer (links an offshore team with a Japanese client) / Communicator (interpreter on the project) Wikipedia: Offshore outsourcing ↗
    ODC / Onsite / Offshore Offshore Development Center (a dedicated remote team) / staff at the client site / staff in the vendor country Wikipedia: Offshore outsourcing ↗
    MM / MD / Effort Man-Month / Man-Day: the units for estimating and billing effort Wikipedia: Man-hour ↗, Wikipedia: The Mythical Man-Month ↗
    Estimation Forecasting effort, cost, and time (bottom-up, analogy, story points) Atlassian: Estimation ↗

    Q&A Sheet Shared log of questions to the client and their answers, used to clarify requirements Wikipedia: Requirements elicitation ↗
    RFI / RFQ Request for Information / Request for Quotation, early steps of procurement Wikipedia: Request for information ↗, Wikipedia: Request for quotation ↗
    MSA Master Service Agreement: umbrella contract; each SOW adds specific work under it Wikipedia: Master service agreement ↗
    Priority / Severity How soon to fix (business order) / how bad the impact is (technical damage) Becoming Senior → Escalation, Wikipedia: Bug tracking system ↗
    P0 / P1 / P2 Priority levels: drop everything / next up / normal queue Codex → GitHub Codex Review

    Onboarding / Handover Bringing someone up to speed / transferring ownership with docs and knowledge Wikipedia: Knowledge transfer ↗

    Wireframe / Mockup / Prototype Low-fidelity layout / high-fidelity static design / clickable or working model Wikipedia: Wireframe ↗, Wikipedia: Prototyping ↗
    Persona / User Journey Archetype of a target user / the steps they take to reach a goal Wikipedia: Persona ↗, Wikipedia: Customer journey ↗
    RTM Requirements Traceability Matrix: links each requirement to its design, code, and tests Wikipedia: Traceability matrix ↗
    Assumption / Constraint Things taken as true without proof / fixed limits (budget, tech, law) Wikipedia: Requirement ↗
