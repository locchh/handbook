## SDLC & Process

| Term                              | Meaning                                                                                                                                     | Read more                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SDLC**                          | Software Development Life Cycle: Analysis → Design → Development → Testing → Deployment → Maintenance                                       | [Lifecycle → SDLC Phases](https://locchh.github.io/handbook/software/basics/lifecycle/#sdlc-phases)                                                                                                                                                                                                              |
| **Waterfall**                     | Sequential phases, each finished before the next starts                                                                                     | [Methodologies → Waterfall](https://locchh.github.io/handbook/software/basics/methodologies/#1-waterfall-do-it-in-order-no-going-back)                                                                                                                                                                           |
| **V-Model**                       | Waterfall where every phase has a matching test level                                                                                       | [Methodologies → V-Model](https://locchh.github.io/handbook/software/basics/methodologies/#2-v-model-for-every-step-define-how-youll-prove-it-worked)                                                                                                                                                            |
| **Agile**                         | Mindset of short iterations, working software, and responding to change                                                                     | [Methodologies → Agile](https://locchh.github.io/handbook/software/basics/methodologies/#3-agile-able-to-move-quickly-and-change-direction-without-losing-balance), [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban)                          |
| **Lean**                          | Eliminate waste, optimize the whole flow of value                                                                                           | [Methodologies → Lean](https://locchh.github.io/handbook/software/basics/methodologies/#2-lean)                                                                                                                                                                                                                  |
| **Scrum**                         | Agile framework of fixed-length sprints with defined roles, events, and artifacts                                                           | [Methodologies → Scrum](https://locchh.github.io/handbook/software/basics/methodologies/#3-scrum-build-a-little-show-it-improve)                                                                                                                                                                                 |
| **Kanban**                        | Continuous flow on a visual board with WIP limits                                                                                           | [Methodologies → Kanban](https://locchh.github.io/handbook/software/basics/methodologies/#4-kanban-finish-before-you-start-something-new)                                                                                                                                                                        |
| **SAFe**                          | Scaled Agile Framework: Agile coordinated across many teams                                                                                 | [Methodologies → SAFe](https://locchh.github.io/handbook/software/basics/methodologies/#5-safe-scrum-but-for-50-teams)                                                                                                                                                                                           |
| **PI**                            | Program Increment: a SAFe timebox of about 10 weeks (several sprints) that all teams plan and deliver together, kicked off by *PI Planning* | [Methodologies → SAFe](https://locchh.github.io/handbook/software/basics/methodologies/#5-safe-scrum-but-for-50-teams), [Wikipedia: SAFe ↗](https://en.wikipedia.org/wiki/Scaled_agile_framework)                                                                                                                |
| **XP**                            | Extreme Programming: pairing, TDD, continuous integration, small releases                                                                   | [Methodologies → XP](https://locchh.github.io/handbook/software/basics/methodologies/#6-xp-extreme-programming)                                                                                                                                                                                                  |
| **Shape Up**                      | Basecamp's fixed-appetite, six-week cycles with no backlog                                                                                  | [Methodologies → Shape Up](https://locchh.github.io/handbook/software/basics/methodologies/#7-shape-up-decide-how-much-time-its-worth-not-how-long-it-takes)                                                                                                                                                     |
| **RUP**                           | Rational Unified Process: iterative phases with formal milestones                                                                           | [Methodologies → RUP](https://locchh.github.io/handbook/software/basics/methodologies/#8-rup-waterfall-iteration-formal-governance)                                                                                                                                                                              |
| **Sprint**                        | Fixed timebox (usually 1–4 weeks) that produces a usable increment                                                                          | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban)                                                                                                                                                                                              |
| **Backlog**                       | Ordered list of work. The *Product Backlog* holds everything wanted; the *Sprint Backlog* holds what this sprint commits to                 | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html)                                                                                                                                   |
| **Increment**                     | The usable, done work produced in a sprint                                                                                                  | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban)                                                                                                                                                                                              |
| **Sprint Planning**               | Scrum event at the start of a sprint: pick backlog items and agree the sprint goal                                                          | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html)                                                                                                                                   |
| **Daily Standup / Daily Scrum**   | 15-minute daily sync: progress toward the sprint goal and blockers                                                                          | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html)                                                                                                                                   |
| **Sprint Review / Demo**          | Show the increment to stakeholders and adapt the backlog from their feedback                                                                | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html)                                                                                                                                   |
| **Retrospective (Retro)**         | End-of-sprint meeting where the team inspects *how* it worked (what went well, what didn't) and commits to improvements                     | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Methodologies → Scrum](https://locchh.github.io/handbook/software/basics/methodologies/#3-scrum-build-a-little-show-it-improve), [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html) |
| **Backlog Refinement (Grooming)** | Ongoing work to split, clarify, and estimate upcoming backlog items                                                                         | [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html)                                                                                                                                                                                                                                                        |
| **Burndown / Burnup Chart**       | Work remaining / work completed plotted over time in a sprint or release                                                                    | [Wikipedia: Burndown chart ↗](https://en.wikipedia.org/wiki/Burndown_chart)                                                                                                                                                                                                                                      |
| **Lead Time / Cycle Time**        | Request → delivered / work started → delivered: the Kanban flow metrics                                                                     | [Lifecycle → Agile, Scrum, Kanban](https://locchh.github.io/handbook/software/basics/lifecycle/#agile-scrum-kanban), [Wikipedia: Lead time ↗](https://en.wikipedia.org/wiki/Lead_time)                                                                                                                           |
| **DORA Metrics**                  | Deployment frequency, lead time for changes, change failure rate, time to restore: the four keys of delivery performance                    | [DORA: Four keys ↗](https://dora.dev/guides/dora-metrics-four-keys/)                                                                                                                                                                                                                                             |
| **DoD**                           | Definition of Done: the shared quality bar every increment must meet                                                                        | [Scrum Guide ↗](https://scrumguides.org/scrum-guide.html), [Atlassian: DoD ↗](https://www.atlassian.com/agile/project-management/definition-of-done)                                                                                                                                                             |
| **DoR**                           | Definition of Ready: what a backlog item needs before a sprint can take it                                                                  | [Atlassian: DoR ↗](https://www.atlassian.com/agile/project-management/definition-of-ready)                                                                                                                                                                                                                       |
| **WIP**                           | Work In Progress, which Kanban limits                                                                                                       | [Methodologies → Kanban](https://locchh.github.io/handbook/software/basics/methodologies/#4-kanban-finish-before-you-start-something-new)                                                                                                                                                                        |
| **DevOps**                        | Dev and Ops share ownership of building and running software                                                                                | [Methodologies → DevOps](https://locchh.github.io/handbook/software/basics/methodologies/#4-devops)                                                                                                                                                                                                              |

| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| **SM**                          | Scrum Master: facilitates the process and removes blockers                                                                                                                                                                 | [Lifecycle → Roles](https://locchh.github.io/handbook/software/basics/lifecycle/#roles)                                                                                                                        |

| **PMO**                         | Project (or Program / Portfolio) Management Office: the group that sets project-management standards, tracks status, budget, and resources across projects, and reports to leadership                                      | [Wikipedia: PMO ↗](https://en.wikipedia.org/wiki/Project_management_office)                                                                                                                                    |
| **PMP**                         | Project Management Professional, the PMI certification                                                                                                                                                                     | [Wikipedia: PMP ↗](https://en.wikipedia.org/wiki/Project_Management_Professional)                                                                                                                              |

| **RFP / SOW**                   | Request for Proposal (a client asks vendors to bid) / Statement of Work (agreed scope, deliverables, timeline)                                                                                                             | [Wikipedia: RFP ↗](https://en.wikipedia.org/wiki/Request_for_proposal), [Wikipedia: SOW ↗](https://en.wikipedia.org/wiki/Statement_of_work)                                                                    |
| **NDA**                         | Non-Disclosure Agreement                                                                                                                                                                                                   | [Wikipedia: NDA ↗](https://en.wikipedia.org/wiki/Non-disclosure_agreement)                                                                                                                                     |
| **T&M / Fixed Price**           | Contract models: pay for time spent / pay an agreed amount for agreed scope                                                                                                                                                | [Wikipedia: T&M ↗](https://en.wikipedia.org/wiki/Time_and_materials), [Wikipedia: Fixed-price ↗](https://en.wikipedia.org/wiki/Fixed-price_contract)                                                           |

| **Go-live / Sign-off**          | The moment the system goes to production users / formal acceptance of a deliverable                                                                                                                                        | [Lifecycle → Environments](https://locchh.github.io/handbook/software/basics/lifecycle/#environments), [Lifecycle → Testing (UAT)](https://locchh.github.io/handbook/software/basics/lifecycle/#testing)       |
| **ROI / TCO**                   | Return on Investment / Total Cost of Ownership (build + run + maintain)                                                                                                                                                    | [Wikipedia: ROI ↗](https://en.wikipedia.org/wiki/Return_on_investment), [Wikipedia: TCO ↗](https://en.wikipedia.org/wiki/Total_cost_of_ownership)                                                              |
| **CapEx / OpEx**                | Capital Expenditure (buy assets up front) / Operating Expenditure (pay as you go, e.g. cloud)                                                                                                                              | [Wikipedia: CapEx ↗](https://en.wikipedia.org/wiki/Capital_expenditure)                                                                                                                                        |
| **POC**                         | Proof of Concept: a throwaway build that shows an idea is feasible                                                                                                                                                         | [Wikipedia: Proof of concept ↗](https://en.wikipedia.org/wiki/Proof_of_concept)                                                                                                                                |
| **MVP**                         | Minimum Viable Product: smallest product that tests the core hypothesis with real users (also *Model-View-Presenter*, see [Frontend](#frontend))                                                                           | [Wikipedia: MVP ↗](https://en.wikipedia.org/wiki/Minimum_viable_product)                                                                                                                                       |
